# 글로벌 계정 · 보안

## NC Shield — 보안 ETL 파이프라인

- **Problem**: 글로벌 게임 보안 트래픽 **30분당 최대 200만 건** — 단일 적재로는 가공·집계 불가
- **Analysis**: 원천 → 가공 → 시각화의 **3단 분리**가 필요. 단계마다 실패 격리 + 재처리 가능해야 함
- **Action**: Kafka → Airflow → MySQL → Airflow → InfluxDB → Grafana 단계별 파이프라인 설계·운영
- **Reflection**: ETL은 한 줄 흐름이 아니라 **단계마다 실패를 허용하는 구조**로 짜야 운영이 가능. 이후 모든 파이프라인의 기본 원칙이 됨

```text
Kafka → Airflow → MySQL → Airflow → InfluxDB ← Grafana
```

`Kafka` `Airflow` `InfluxDB` `Grafana` `Kotlin` `Spring` `graphQL`

> Note: 단순히 ETL을 짠 게 아니라, 단계마다 실패가 격리되도록 끊어 놓아야 운영이 가능하다는 점을 학습한 프로젝트.

## 문제 앞에서의 사고 과정

1. **이게 왜 문제인가?** — 증상이 아니라 원인을 묻기
2. **진짜 원인이 맞나?** — 첫 가설을 의심, 재현 환경부터 만들기
3. **더 싸게 풀 수 있나?** — 요구사항 재정의·도메인 특성으로 우회 가능한지
4. **운영이 가능한가?** — 장애 시나리오·대응 동선까지 상상
